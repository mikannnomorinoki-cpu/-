# 個人サイト制作プロジェクト 引き継ぎメモ

## 1. 制作したいサイト

自分だけの個人サイトを作りたい。

### 基本方針
- PC・スマートフォンの両方に対応。
- URLを知っている人がアクセスできる形で公開する。
- できるだけ簡単に制作・管理できること。
- 基本的に完全無料で運用する。
- クレジットカードは持っていないため、カード登録が必要なサービス・プランは利用しない。
- 有料サービスを使うとしても、買い切り1,000円未満で、PayPayまたはコンビニ払いが可能な場合に限り検討する。
- 月額課金や自動課金は基本的に不可。
- 無料枠を超えたときに自動で課金される構成にはしない。

## 2. デザインの方向性

コンセプトは、

**POP × SPARKLE × SIMPLE**

### 色
- クリーム色
- 黄色
- オレンジ色
- シアン寄りの青を差し色にする

### 雰囲気
- ポップで明るい
- キラキラ・ツヤ感・透明感
- ふんわりしすぎず、少しシャープ
- シンプルで余白を活かす
- 星や光の装飾はポイント使いにする
- ごちゃごちゃさせない

PCとスマホでデザインの雰囲気を保ちながら、それぞれに適したレイアウトにする。

## 3. サイトに欲しいページ・機能

現在想定しているページ：
- HOME
- PROFILE
- CREATION（作品）
- LOG（日記・記録）
- NEWS（お知らせ）
- ARTICLE（個別記事）

### 投稿機能
- Newsと通常投稿を分ける。
- 投稿は新しい順に表示。
- 投稿がない場合は案内を表示。
- 記事ごとのページを作る。
- 画像・動画などのファイルを扱えるようにする。
- すべてのリンク・メニューが機能すること。

### 管理画面（重要・必須）
最終的には、サイト内に管理者専用の投稿画面が欲しい。

希望する機能：
- 管理者だけがログインできる。
- 投稿種類（News・Log・Creationなど）を選べる。
- タイトル・本文・日付を入力できる。
- 画像・動画を選んでアップロードできる。
- 投稿・保存ボタンで公開できる。
- 下書き保存ができる。
- 過去の投稿を編集・削除できる。
- 投稿後はサイトに自動反映される。
- PC・スマホの両方から管理できる。

**投稿のたびにGitHubでプログラミングコードを書く方式は嫌。管理画面から投稿したい。**

## 4. 現在登録済みのサービス

### GitHub
- アカウント作成済み。
- `<username>.github.io` 形式のPublicリポジトリを作成済み。
- READMEあり。
- GitHub Pagesはまだ公開設定していない。

### Cloudinary
- アカウント作成済み。
- 画像・動画などの保存・配信に使う予定。
- Upload presetを作成済み。

設定内容：
- Upload preset name：`my-site-uploads`
- Signing mode：`Signed`
- Asset folder：`my-site`
- Overwrite assets with the same public ID：OFF
- Generated public ID：Auto-generate an unguessable public ID value
- Generated display name：Use the filename of the uploaded file as the asset's display name

CloudinaryのCloud nameとAPI Keyは確認済み。
API SecretもDashboardで確認できるが、チャットには絶対に貼らないこと。

Signed Uploadにはサーバー側での署名生成が必要。API Secretをフロントエンドに公開してはいけない。

## 6. これまで検討した構成

候補として考えたもの：

- GitHub Pages：サイト公開
- Cloudinary：画像・動画の保存・配信
- Cloudflare Workers：Cloudinaryの署名API
- Firebase：管理者ログイン・投稿データ保存

ただし、Cloudflare Workersはカード登録を求められる可能性があるため、現在は採用保留。
R2は使わない。バケットも作成していない。

Firebase Sparkはカード不要の無料プランとして候補に挙がったが、まだ登録していない。
Firebaseへの追加登録はまだ決定していない。

## 7. 最優先の条件・注意事項

1. クレジットカード登録が必要なサービスは絶対に使わない。
2. 有料プランへの変更や支払い情報入力を求められたら、そこで停止する。
3. 自動課金が発生しない構成にする。
4. できる限りサービスの登録数を増やさない。
5. まずGitHubとCloudinaryだけでどこまで実現できるか検討する。
6. 管理画面は妥協せず、最終的に実装したい。
7. セキュリティを無視した簡易ログインや、誰でもアップロードできる設定にはしない。
8. API Secret・パスワード・トークンをチャットに貼らせない。
9. 無料で実現できるか確かめずに、安易に新しいサービスを登録させない。
10. 仕様や無料枠は公式情報で確認してから案内する。

## 8. 次にやること

まずGitHubのリポジトリ画面を確認する。

そのうえで、
- 現在のファイル構成・コードを把握する。
- GitHubとCloudinaryだけで管理画面を実現できるか検討する。
- 難しい場合は、カード不要・無料枠ありの追加サービスを最小限だけ候補にする。
- 追加登録が必要なら、登録前に必要性と無料条件を説明する。
- 管理画面、ログイン、投稿保存、画像・動画アップロードを実装する。
- 最後にGitHub Pagesで公開する。

## 9. ユーザーへの案内方法

- 日本語で、明るく親しみやすく説明する。
- 初心者向けに操作を具体的に案内する。
- GitHubの画面は英語なので、英語のボタン名も併記する。
- 一度に細かい修正を何度もさせない。
- できるだけ完成形に近いコードをファイル単位で提示する。
- 「全置換」か「末尾に追加」かを必ず明記する。
- ファイル保存を確認してから次の作業に進む。
- ユーザーの許可なく有料登録やカード登録へ誘導しない。

**今回の最重要目標：カード不要・基本無料・少ないサービス数で、管理画面から簡単に投稿できる個人サイトを完成させること。**
